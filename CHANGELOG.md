# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `Ark.Tools.MediatorFramework.MinimalApi`: `services.AddArkMessagePack(resolver)` registers the MessagePack resolver for generated Minimal API endpoints and builds their serializer options once.

### Changed

- `ARKCORE002`, `ARKCORE003` and `ARKCORE004` are now reported on each `EvolvableEnum<T>` usage instead of the enum declaration, so an invalid enum used N times no longer shows N identical errors at its declaration and IDE analysis shows the error in the file that uses the enum. The enum declaration (or the clashing members for `ARKCORE003`) is attached as an additional location. A `#pragma` or `[SuppressMessage]` that targets these rules must now be placed at the usage.
- `ComplianceLayout` no longer builds an extra copy of each log line when PII scanning is off (the default), so the layouts set by `NLogConfigurer` allocate less per event.
- `Ark.Tools.NLog`: with PII scanning on, console, file, debugger and mail text lines scan only the message and exception text, not the timestamp, level and logger prefix, so log events without PII-like content no longer pay for the regex.
- Generated sensitive value objects (`EmailAddress`, `PersonName`, ...) format into a span (`TryFormat`, used by NLog, string interpolation and `StringBuilder`) without allocating, and `ToString()` and `ComplianceRedactor.Redact` allocate at most one string; the output is unchanged.
- `Ark.Tools.FtpClient.SftpClient`: `DownloadFileAsync` sizes its buffer from the remote file and returns it without a final copy, so a download allocates about the file size instead of about 3x.
- `Ark.Tools.MediatorFramework.Mcp`: MCP attachment uploads larger than the size limit are rejected before the base64 is decoded, and attachment downloads read seekable streams into an exact-size buffer, so large attachments use about half the memory.
- `Ark.Tools.Http`: `BufferedJsonMediaTypeFormatter` no longer copies an already-buffered response body into a second buffer, halving memory for large JSON responses, and the MessagePack Flurl helpers reuse one serializer options and formatter per resolver instead of creating them on each call.
- `Ark.Tools.MediatorFramework.Messaging.Azure`: the Azure Blob DataBus reads a payload attachment with a single request instead of two, so large messages start processing sooner.
- **Breaking:** `Ark.Tools.MediatorFramework.Mcp`: the MCP generator no longer reads the XML documentation of referenced assemblies from disk. Tool descriptions still come from `[Description]` attributes, from the contract's own XML documentation and from XML documentation files passed as `AdditionalFiles`. The MCP package passes referenced projects' XML documentation to the generator automatically, as `<AssemblyName>.arkmcpdoc` copies in the intermediate output so other generators (such as the ASP.NET Core OpenAPI one) do not read them; opt out with `ArkMcpIncludeReferencedXmlDocs=false`. Contracts from referenced NuGet packages that are described only by XML documentation need `ArkMcpIncludePackageXmlDocs=true`, or their XML file added as `AdditionalFiles`, to keep their descriptions.
- **Breaking:** `Ark.Tools.MediatorFramework.MinimalApi` hosts with MessagePack endpoints must call `services.AddArkMessagePack(resolver)` instead of registering `IFormatterResolver` directly; without it they fail with an `InvalidOperationException` at startup, or on the first MessagePack response for hosts whose MessagePack endpoints only return data.
- `Ark.Tools.MediatorFramework.MinimalApi`: MessagePack responses of generated Minimal API endpoints are written straight to the response pipe, and the serializer options and `Accept` parsing no longer allocate per request; the bytes on the wire are unchanged.
- **Breaking:** `Ark.Tools.MediatorFramework`: `[McpTool]` contracts are now part of `ArkApiSurface.txt`, with an `[mcp=<tool name>]` tag on their `CONTRACT` line, and MCP-only contracts now list their fields and result type. Each `CONTRACT` line with an HTTP, gRPC or MCP transport now has a single `[version=<range>]` tag after the transport tags, and `[grpc-version=<range>]` is gone. Projects with gRPC or MCP contracts get `ARKAPI002` on upgrade; regenerate and commit `ArkApiSurface.txt` to accept it.
- `Ark.Tools.Compliance.Sql`: the task that writes the compliance SQL scripts now ships precompiled in the package (`tasks/netstandard2.0`) instead of being compiled on every MSBuild node, so clean builds of compliance-enabled projects are a few seconds faster.
- **Breaking:** `Ark.Tools.FtpClient.Core`: `FtpClientBase.MaxListingRecursiveParallelism` and the `FtpClient` and `FtpClientBase` constructor overloads taking a listing parallelism are removed, as they had no effect; drop the `int` argument. `FtpClient` still lists recursively on one connection, one folder at a time.
- `FtpClientPool.ListFilesRecursiveAsync` now lists folders in parallel on up to `PoolMaxSize` pooled connections, and the FTP ResourceWatcher lists its `FoldersToWatch` at the same time, so listing large trees is faster. The order of the listed files is no longer the folder walk order.

### Fixed

- `Ark.Tools.MediatorFramework.Mcp`: an MCP contract property whose setter the generated tool cannot call (for example `private set` or `protected init`) and that no constructor takes now reports `ARKMF053`, instead of generating code that fails with CS0272.
- `Ark.Tools.MediatorFramework.Mcp`: MCP tools now include the properties a contract inherits from its base types and use the same versioning defaults as the other transports, so a contract with `[Versioning]` but no `Introduced` is available from version 1.
- `Ark.Tools.MediatorFramework`: contracts that override a base property or hide it with `new` now get one binding for it, from the most-derived declaration. Before, the Minimal API and Azure Functions endpoints failed to compile and gRPC mapped the property twice.
- `Ark.Tools.MediatorFramework.AzureFunctions`: HTTP endpoints returning `IAsyncEnumerable<T>` now stream items as they are produced, as on the Minimal API host. Before, the generator never detected the streaming response and buffered the whole result.
- `AuthenticationApiClientCachingDecorator` stops serving a cached token 60 seconds before it expires, so callers (including `BasicAuthAuth0ProxyMiddleware`) no longer get a token that expires in flight and fails with 401. A token valid for 60 seconds or less is not cached.
- `Ark.Tools.MediatorFramework.MinimalApi`: an `Accept` header with a fractional MessagePack quality such as `application/x-msgpack;q=0.5` now gets a MessagePack response. Before, any `q` value starting with `0` was treated as a refusal and the response was JSON; now only `q=0` refuses MessagePack.
- `Ark.Tools.AspNetCore.BasicAuthAuth0Proxy` and `Ark.Tools.AspNetCore.BasicAuthAzureActiveDirectoryProxy` no longer retry a login rejected by the identity provider, such as a wrong password. One bad Basic-auth request now counts as one failed login instead of three or four, so users are not locked out sooner, and on Auth0 it fails at once instead of after up to 6 seconds. Network errors, timeouts, 408, 429 and 5xx responses are still retried, and an aborted request stops the retries.
- `Ark.Tools.MediatorFramework`: the Minimal API generator now collapses line breaks and repeated whitespace in `[Description]` text, as the gRPC generator already did, so a contract gets the same OpenAPI summary and gRPC comment on both transports.
- `Ark.Tools.MediatorFramework`: the Minimal API and gRPC generators now keep a space at `<br/>` and between `<para>` blocks in XML documentation, so `First line.<br/>Second line.` becomes `First line. Second line.` in OpenAPI summaries and gRPC comments instead of `First line.Second line.`.
- `Ark.Tools.MediatorFramework`: an empty or whitespace-only `[Description]` (including `[Description]` with no argument) no longer hides a contract's or property's XML documentation from the Minimal API OpenAPI metadata and gRPC comments; the XML `<summary>` and `<remarks>` are used instead. A `[Description]` with text still takes precedence. The MCP generator is unchanged.
- `Ark.Tools.MediatorFramework`: the Minimal API and gRPC generators no longer drop words from XML documentation. `<see langword="null"/>` becomes `null`, `<paramref name="id"/>` and `<typeparamref name="T"/>` become the parameter name, and `<see href="url">text</see>` becomes its text, or the URL when it has none, in OpenAPI summaries and gRPC comments. Before, `Returns <see langword="null"/> when missing.` became `Returns when missing.`.
- `Ark.Tools.MediatorFramework.MinimalApi`: Minimal API endpoints with `AcceptsMessagePack` now read and write JSON with the `JsonTypeInfo` from the host's HTTP JSON options, so Native AOT publishes no longer report IL2026/IL3050 from Ark.Tools for them. If those options have no metadata for a request or response type, the JSON call now throws `NotSupportedException` instead of falling back to reflection.
- `Ark.Tools.AspNetCore.BasicAuthAzureActiveDirectoryProxy` now forwards the access token returned by Azure AD. Before, it never read `access_token` from the token response and sent an empty `Authorization: Bearer` header, so every basic-auth request failed authentication.

## [7.0.0-beta18] - 2026-10-15

### Changed

- **Breaking:** Rebus consumers using `OpenTelemetryStep` now treat the sender of a message as a remote parent, as incoming HTTP requests and MediatorFramework messages already did. With the default `RespectRemoteParentSampling = false`, a Rebus worker samples its messages with its own `TracesPerSecond` budget instead of following the sender's sampled flag, so you will see more worker spans and some traces that start in the middle of a chain. To keep the previous behaviour, set `OTel:ArkAdaptiveSampler:RespectRemoteParentSampling` to `true`; it then applies to every remote parent of the host, incoming HTTP requests included.
- **Breaking:** the Ark OpenTelemetry setups (`AddArkOpenTelemetry`, `AddArkAspNetCoreOpenTelemetry`, `AddArkOpenTelemetryForWorkerHost`) no longer register `WebApi4xxAsSuccessProcessor`, so a server 4xx span keeps the status its producer set. The ASP.NET Core instrumentation leaves 4xx requests `Unset`, so nothing changes for them; a 4xx request that the application or an unhandled exception marked as `Error` now stays failed and is promoted by failure promotion. Application Insights shows `Unset` 4xx requests as failed whether or not the processor runs: to show them as successes, set `ActivityStatusCode.Ok` in your own processor, see [HTTP 4xx status](docs/otel/sampling.md#http-4xx-status). To keep the previous behaviour, register `WebApi4xxAsSuccessProcessor` yourself before the Ark setup.
- **Breaking:** `ArkFailurePromotionProcessor` promotes a span only when its status is `Error`. An `Unset` or `Ok` span with an `exception` event, an HTTP 5xx code or a gRPC error code is no longer promoted, because the code that produces a span decides whether it failed. The instrumentations Ark wires set `Error` on failures, so their failures are still kept. If your own code records an exception on a span (`AddException`) without setting the status, also call `SetStatus(ActivityStatusCode.Error)` to keep promoting it.
- `Ark.Tools.MediatorFramework`: with `ArkApiSurfaceEnabled=false` the API surface generator no longer reads your contracts or emits `ArkApiSurface.g.cs`, so opted-out projects no longer pay for the surface on each edit and build.

### Deprecated

- `WebApi4xxAsSuccessProcessor` (in `Ark.Tools.OTel` and `Ark.Tools.AspNetCore.ApplicationInsights`) is obsolete: it erases an `Error` set on purpose and does not make Application Insights count 4xx requests as successful. Set `ActivityStatusCode.Ok` in your own processor instead.

### Fixed

- `OpenTelemetryStep` now sends the W3C trace state of the current span in the `TraceStateString` header. The receiving step already read that header, but no sender wrote it, so trace state was lost across Rebus messages.
- `ArkGrpcErrorInterceptor` marks the request span as `Error`, with `error.type`, when it maps an unexpected exception to the gRPC `Internal` status. Before, the span stayed `Unset` because the call ends with HTTP 200, so failed gRPC calls were not kept by failure promotion.

## [7.0.0-beta17] - 2026-10-14

### Added

- `Ark.Tools.MediatorFramework.Mcp`: `McpToolSerializerOptions.Get(services)` returns the JSON options used by generated MCP tools. Attachment tools now also work under Native AOT (or with reflection-based JSON disabled), because the MCP protocol and attachment contracts are appended after your own resolvers.
- `Ark.Tools.FtpClient.FtpProxy`: `IFtpClientProxyConfig.AcceptAnyServerCertificate` (default `false`) accepts any TLS certificate from the FtpProxy service. It disables certificate validation, so use it only with a development proxy that has a self-signed certificate.

### Changed

- `Ark.Tools.MediatorFramework.Mcp`: generated MCP tools serialize arguments and structured results with the Minimal API JSON options (`ConfigureHttpJsonOptions`) instead of the MCP SDK defaults, so MCP returns the same shape as the HTTP endpoints (for example `EvolvableEnum` values as names).
- `DataKeyComparer` and `DataKeyHashSet` compare and hash key properties without boxing or reflection on each call, about 3x faster on large row sets (Native AOT keeps the reflection path).
- `StorageQueueMessagingTransport`: when the transport creates its own client from a connection string or a service URI, lock renewal and abandon update only the message visibility instead of uploading the message body again, so each renewal sends no payload. A transport over an application-supplied `QueueServiceClient` still sends the body, because that client may use client-side encryption.
- Compliance surface (`ArkComplianceSurfaceEnabled`): editing a method with many `Register` calls, such as a SimpleInjector composition root, no longer slows down the IDE, because DI container registrations are no longer analysed as serializer registrations and the remaining calls share one binding per file.
- **Breaking:** `Ark.Tools.FtpClient.FtpProxy` now validates the TLS certificate of the FtpProxy service, which receives the bearer token and the FTP credentials; before, any certificate was accepted. A proxy with a self-signed or otherwise untrusted certificate now fails with a `FlurlHttpException` caused by an `AuthenticationException`: trust its certificate, or return `true` from `AcceptAnyServerCertificate` in your `IFtpClientProxyConfig` for development only.
- The MediatorFramework Minimal API, gRPC, Rebus, MCP and Azure Functions source generators no longer keep an earlier copy of the project's compilation alive in the IDE between edits, which lowers IDE memory use.
- `MessagingOutboxProcessor` sends each batch of outbox messages to its different queues and topics concurrently, so the outbox drains faster when it targets several destinations. Messages to the same queue or topic are still sent one at a time in outbox order; there is no ordering between different destinations.
- `Ark.Tools.MediatorFramework.Grpc`: a build that leaves the gRPC host assembly unchanged no longer starts the `.proto` exporter. It runs again when the assembly, an `ArkAdditionalProto` file or the package changes, when any exported file is missing, or when `ArkExportProtoDir` points to a directory not exported since the last change.
- `Ark.Tools.MediatorFramework`: `ArkApiSurface.current.txt` in `obj/` is copied only when the generated API surface changes, and `dotnet clean` now removes it.
- `Ark.Tools.Outbox.SqlServer`: `SendAsync` writes up to 1,000 messages in one `INSERT` statement instead of one statement per message, so sending many messages takes far fewer round trips inside the business transaction. Messages keep their order.
- `Ark.Tools.MediatorFramework`: with `EmitCompilerGeneratedFiles=true`, generated files now go to `obj/<Configuration>/<TargetFramework>/generated` instead of `obj/generated`, so Debug and Release builds no longer overwrite each other's files. A `CompilerGeneratedFilesOutputPath` you set yourself is still used.
- The ARKPII001 code fix no longer offers *Use sensitive value object*, so its light bulb appears without first searching the whole solution for references. Use the *Use sensitive value object* refactoring on the classified property instead.

### Fixed

- `Ark.Tools.MediatorFramework.Mcp`: attachment downloads now return the MCP `blob` as base64, as the protocol requires. Before, the raw bytes were sent, so MCP clients that decode the blob (for example `BlobResourceContents.DecodedData`) failed or got corrupted data.
- `Ark.Tools.Sdk`: Reqnroll code-behind (`*.feature.cs`) is now generated in `obj/` as documented when `Directory.Build.props` imports the SDK props, so the build after a clean no longer recompiles every Reqnroll test project; run `dotnet clean` once to delete the old code-behind files from the project folders.
- `DataKeyComparer` and `DataKeyHashSet`: a null key property no longer resets the hash code, so rows that differ only in the keys before a null key no longer collide and slow the set down.
- `Ark.Tools.Outbox.SqlServer`: the outbox now dispatches the oldest messages first, in the order they were written. Before, it sent the newest first, so under load old messages could wait indefinitely and the messages of one transaction went out in reverse order.
- ARKPII005 is reported once per string concatenation, on the whole expression, instead of once per `+`; long concatenations are now analysed as a whole.
- `Ark.Tools.MediatorFramework.Messaging`: receiving a Protobuf message no longer blocks a thread-pool thread while a claim-checked (DataBus) payload downloads, and cancellation now stops that download.
- `SqlStateProvider`: `LoadStateAsync` and `SaveStateAsync` now pass their cancellation token to SQL Server, so stopping a ResourceWatcher no longer waits for a slow or blocked state query to time out.
- `Ark.Tools.FtpClient.SftpClient`: SFTP downloads and uploads now stop when their cancellation token is cancelled, so `DownloadTimeout` and host shutdown no longer wait for a stalled transfer. A cancelled or failed transfer now closes its connection, so a pool no longer reuses a connection left with a transfer half done.

### Security

- Ark.Tools packages now depend on `System.Security.Cryptography.Pkcs` and `System.Security.Cryptography.Xml` 10.0.13, which fix GHSA-846f-f764-76mx, GHSA-2fmv-rv2c-59x7, GHSA-r955-8q5j-3h83, GHSA-7hqp-7c5m-4vq6 and GHSA-c399-9853-6jmj; earlier 10.0.x versions came in transitively.

## [7.0.0-beta16] - 2026-10-13

### Added

- `ArkAdaptiveSamplerOptions.RespectRemoteParentSampling`: set it to `true` to have the W3C sampled flag of a remote parent decide which spans the service exports, as before this release.
- `Ark.Tools.OTel`: `AddArkOpenTelemetry()` registers the Ark OpenTelemetry pipeline (adaptive sampler, failure promotion, redaction, `HttpClient` and SQL Client instrumentation, the Outbox source and meter, and HTTP client and .NET runtime metrics) on any host, without referencing ASP.NET Core. Pass an `IConfiguration` to bind the sampler from `OTel:ArkAdaptiveSampler`. `AddArkAspNetCoreOpenTelemetry` builds on it.
- `Ark.Tools.OTel.Azure`: a new package with the Azure wiring for any host, such as a WorkerHost. `AddArkAzureSdkInstrumentation()` collects Azure SDK spans (Service Bus included), drops the `HttpClient` span nested under an Azure SDK span and keeps Service Bus receives out of the sampler budget; `AddArkAzureOpenTelemetry(configuration)` also adds the Azure App Service, Virtual Machine and Container Apps resource detectors (cloud role instance, region and resource ID; `service.name` stays the entry assembly name, so a web app and its WebJobs stay apart) and exports traces, metrics and error logs to Azure Monitor when a connection string is configured.
- `ArkAdaptiveSamplerOptions.Filter`: a callback applied before sampling, from the span name, kind, parent and creation tags; return `false` to drop the span, so it does not use the budget. The Ark setups compose their own rules onto it, so an application filter is kept.

### Changed

- **Breaking:** `ArkAdaptiveSampler` no longer follows the sampling decision of a remote parent by default: spans with a remote parent use the local budget and carry this service's sample rate, so callers using a different sampler, such as the classic Application Insights SDK, no longer decide which spans the service exports. Set `RespectRemoteParentSampling` to `true` to restore the previous behaviour.

- `ArkAdaptiveSampler`: `TracesPerSecond` is now the total budget of root traces shared by all operation buckets, instead of a budget for each bucket, so a service with many operations no longer exports up to `TracesPerSecond` traces per operation. Rare operations get a share that covers their average traffic; raise `TracesPerSecond` if you relied on the per-operation budget. `MovingAverageRatio` now smooths only rate increases: rates drop to their new share at once.
- `Ark.Tools.ResourceWatcher.OTel`: `AddArkOpenTelemetryForWorkerHost` now adds the full Ark pipeline, so worker hosts get adaptive sampling, failure promotion, and `HttpClient` and SQL Client spans, in addition to the ResourceWatcher source and meter. The sampler reads `OTel:ArkAdaptiveSampler` from the host configuration.
- **Breaking:** `Ark.Tools.AspNetCore.OTel` adds only the ASP.NET Core setup: `AddArkAzureMonitorOpenTelemetry` is removed and the package no longer references the Azure Monitor Distro (`Azure.Monitor.OpenTelemetry.AspNetCore`) or `Ark.Tools.OTel.Azure`. A web host on Azure calls both helpers, as a worker host does: reference `Ark.Tools.OTel.Azure` and replace `services.AddArkAzureMonitorOpenTelemetry(configuration)` with `services.AddOpenTelemetry().AddArkAspNetCoreOpenTelemetry(configuration: configuration).AddArkAzureOpenTelemetry(configuration)`. Azure Monitor export now uses `Azure.Monitor.OpenTelemetry.Exporter`: URL query strings stay redacted, which the Distro turned off, and the Application Insights profiler tagging and the Azure SDK log forwarder are no longer added; reference the Distro yourself if you need them. `AddArkAspNetCoreOpenTelemetry` takes an optional `configuration`, and `AddArkAzureOpenTelemetry(configuration)` now reads the legacy `ApplicationInsights:ArkAdaptiveSampler` section.
- **Breaking:** `WebApi4xxAsSuccessProcessor` moved from `Ark.Tools.AspNetCore.OTel` to `Ark.Tools.OTel` (namespace `Ark.Tools.OTel`). Update the `using` if you register it yourself.
- **Breaking:** `ArkPreFilterProcessor` no longer drops Azure Service Bus receive spans. The Azure setups drop them before sampling, through `ArkAdaptiveSamplerOptions.Filter` and `AzureSamplingFilters.IsServiceBusReceive` from `Ark.Tools.OTel.Azure`; the Application Insights setup applies the same rule without referencing that package. Only `ServiceBusReceiver.Receive` is dropped: settlement and lock renewal spans (`ServiceBusReceiver.Complete`, `DeadLetter`, `RenewMessageLock`, …) are no longer hidden and follow the sampling decision of the message processing span.
- `Ark.Tools.AspNetCore.OTel`: `AddArkAspNetCoreOpenTelemetry` now collects ASP.NET Core server spans and request metrics with any exporter, not only through the Azure Monitor Distro. Azure Functions workers, whose host already reports each request, should call `AddArkOpenTelemetry` instead. On .NET 10 it also sets the `Microsoft.AspNetCore.Hosting.SuppressActivityOpenTelemetryData` switch to `false`, as ASP.NET Core 11 does by default, so request tags are known when the span is created and `OPTIONS` requests are dropped before sampling.
- Azure SDK spans, Azure Service Bus included, are collected only by the `Ark.Tools.OTel.Azure` setups (`AddArkAzureSdkInstrumentation` and `AddArkAzureOpenTelemetry`), with or without an Azure Monitor connection string. They turn the `Azure.Experimental.EnableActivitySource` switch on unless the application or the `AZURE_EXPERIMENTAL_ENABLE_ACTIVITY_SOURCE` environment variable already set it, and drop the `HttpClient` span nested under an Azure SDK span, as the Azure Monitor Distro does. `AddArkAspNetCoreOpenTelemetry` no longer registers the `Azure.Messaging.ServiceBus` source.

- The adaptive sampler is now configured from the `OTel:ArkAdaptiveSampler` section. `AddArkAzureOpenTelemetry(configuration)` still reads `ApplicationInsights:ArkAdaptiveSampler` for compatibility, but `OTel:ArkAdaptiveSampler` values take precedence. The Azure Monitor connection string is still read from `ApplicationInsights:ConnectionString`.

### Fixed

- `ArkAdaptiveSampler` marks the spans it samples with their Azure Monitor sample rate (`microsoft.sample_rate`), so item counts can add up to the real request and dependency volumes; spans kept because of a failure count once. `Azure.Monitor.OpenTelemetry.Exporter` 1.10.0 does not read the attribute yet, see [Sample rate and item counts](docs/otel/sampling.md#sample-rate-and-item-counts).
- The Azure setup keeps an application `HttpClient` filter (`FilterHttpRequestMessage`) registered before it; the Azure Monitor Distro used to replace it with its own filter.
- `ArkAdaptiveSampler`: only the roots its bucket logic decides count in the `TracesPerSecond` budget. SQL commits, HTTP `OPTIONS` requests whose method is known at creation, writes to the NLog database and Service Bus receives are dropped before sampling. SQL commands skipped by query label (such as the outbox polling query) or by an application SqlClient filter, and spans the Ark pre-filter or NLog database processors drop after they start, give their token back.
- `Ark.Tools.OTel.Azure` sets `Azure.Experimental.EnableActivitySource` in the application's runtime configuration, because Azure.Core reads it only when the first Azure SDK client starts: Service Bus and Event Hubs spans are now collected even when Key Vault or App Configuration clients start before the Azure setup. Set the MSBuild property `ArkEnableAzureSdkActivitySource` to `false` to opt out; the `AZURE_EXPERIMENTAL_ENABLE_ACTIVITY_SOURCE` environment variable has no effect while the runtime configuration sets the switch.
- `ArkSqlDependencyFilterProcessor` matches the NLog database server by host name or its short name, instead of any server name containing it: `notlogs.example.com` no longer matches `logs.example.com`.
- `ArkAdaptiveSampler`: an application `Filter` that throws keeps the span instead of failing the code that starts it.
- `ArkAdaptiveSampler`: operations with less than one root every two seconds, such as a periodic job or a health check, keep being sampled at low traffic and next to busy operations. Before, their buckets could never hold a whole token after the first rate adjustment, so they were no longer sampled until the process restarted.
- OpenTelemetry setups given configuration now drop the SQL spans of NLog's own database writes (`ConnectionStrings:NLog.Database`), as the Application Insights setup does. `ArkSqlDependencyFilterProcessor` now also matches a `tcp:` server prefix and a named SQL Server instance.

## [7.0.0-beta15] - 2026-10-13

### Added

- Mediator Framework: a [contract design checklist](docs/mediator-framework/contract-design-checklist.md) covering fields and updatability, validation, business rules, failures, API design, authorization, versioning, privacy and more. The `ark-mediator-framework` agent skill now drafts a contract brief from it and asks for confirmation before writing code.
- `Ark.Tools.Outbox`: `OutboxScope`, an ambient outbox transaction like Rebus's `RebusTransactionScope`. Messages sent through a bus while it is open are staged and written to the application outbox on `CompleteAsync`. It works with the Mediator Framework native bus and with Rebus configured with `Outbox(...)`; Rebus code that calls `bus.Enlist(context)` works as before, and that enlistment takes precedence over an enclosing scope.

### Changed

- **Breaking:** public classes and records that nothing in Ark.Tools derives from and that declare no `virtual` members are now `sealed`, so the JIT can devirtualize calls to them. Types such as the Rebus steps and decorators, the Solid decorators, the JSON converters, the MessagePack formatters, the authorization handlers, the Swashbuckle filters and the exceptions in `Ark.Tools.Core` can no longer be subclassed; wrap or decorate them instead.
- `EvolvableEnumTypeConverter` throws the parser's own exception for an invalid value instead of wrapping it in a `TargetInvocationException`.
- Lower per-call overhead on hot paths: messaging send, receive and metrics, Rebus steps, outbox polling, authorization handlers, Minimal API forwarded-prefix and ETag handling, comma-separated value providers, ResourceWatcher runs, OTel redaction and file export, RavenDB auditing, `ServiceProvider*Processor` untyped dispatch and the Newtonsoft `ValueCollectionConverter`. ResourceWatcher and `WorkerHost` now enumerate a provider's resource sequence once per run.
- **Breaking:** Mediator Framework handlers open an `OutboxScope` instead of casting `IBus` to `IBusOutboxEnlistment`: replace `((IBusOutboxEnlistment)bus).Enlist(context)` with the new `bus.Enlist(context)` extension, which opens an `OutboxScope` like the Rebus helper of the same name. Every native bus stages the sends made in an open scope, so `UseOutbox()` is optional again; `UseOutbox(outbox => outbox.UseDevelopmentPassthrough())` still sends directly during development without changing the handlers. `RebusMessagingBus` with `outboxEnabled: false` throws when a message is sent in an open scope.
- Mediator Framework, Compliance and `Ark.Tools.Core` source generators do less work on each edit, which keeps the IDE more responsive in large solutions; generated code is unchanged.
- The MCP tool generator keeps only the XML documentation entries its tools use and no longer reparses documentation files when an unrelated XML file changes, which uses less memory and keeps the IDE more responsive.
- The Azure Functions messaging generator no longer scans every type of the participant assembly on each edit to find its messaging network, keeping the IDE responsive in large projects.
- The Mediator Framework API surface generator no longer regenerates `ArkApiSurface.g.cs` or re-compares the `ArkApiSurface.txt` baseline when an edit only moves contracts to other lines, keeping the IDE more responsive.
- The Mediator Framework messaging network and gRPC generators do less work while you type: moving code around no longer rebuilds messaging files, and after an edit the generated files it does not affect are reused instead of rebuilt.
- Mediator Framework: in a host project that declares no `[GrpcMethod]` contracts itself, the gRPC generator reads `[ProtoContract]` types only from the assemblies its mapping calls select and the assemblies they reference, so the IDE rescans less after you edit a referenced project, and reordering mapping calls no longer triggers a rescan.
- The Minimal API, Rebus and MCP source generators of `Ark.Tools.MediatorFramework` and the `Ark.Tools.Compliance` surface generator no longer regenerate code when an edit only moves declarations to other lines, which keeps the IDE responsive while editing.
- `Ark.Tools.Compliance`: when the surface gate (`ArkComplianceSurfaceEnabled`) is off, which is the default, the compliance surface generator skips the semantic analysis of every type and SimpleInjector registration on each build and edit, and does not generate `ArkComplianceSurface.g.cs`.
- `Ark.Tools.Compliance.Sql`: builds skip regenerating the SQL policy scripts when the generated policies and `ArkComplianceSqlToken` values are unchanged, saving the 1–2 seconds MSBuild spent compiling the inline task in each build.
- Mediator Framework generators match attributes without formatting a display string for every attribute they inspect, so their work grows less with the number of contracts and members.
- `Ark.Tools.Compliance`: with the surface gate on, the compliance surface generator does less work per member on each build and edit, classifying each value type once instead of once per member, which roughly halves its allocations.

### Removed

- **Breaking:** `IBusOutboxEnlistment`, `IBusOutboxScope` and `MessagingOutboxMode.None`. An absent query value ignores the property initializer: a non-nullable one, such as `int Count { get; init; } = 1` or a `string` declared outside a nullable context, fails with `400` as a missing required parameter, and a nullable one binds `null`. Enum names in another case used to be accepted.
- `ArkTypeConverter.TryConvertSafe` throws `InvalidOperationException` naming the missing registration when the target type is not registered, instead of a `TypeInitializationException`.
