# Build time and hot-path review (October 2026)

## Scope

A whole-repository pass for build time (CI and local iteration) and for
per-call costs in library code that runs per span, request, message, payload or
row. Every change keeps public APIs and observable behavior.

Measured on a 4-core, 15 GB Linux container with the .NET 10.0.401 SDK, Debug
configuration, after `dotnet restore --locked-mode`.

## Build time

### Finding: duplicate reference-graph builds broke incremental builds

`Ark.Reference.Core.Database.sqlproj` collected compliance SQL policies with
`<MSBuild Targets="ArkGenerateComplianceSqlStandalone" Properties="ArkComplianceSqlOutputPath=…;EnableArkToolsCompliance=true">`.
Global properties flow through `ProjectReference`, so each call built the
target project **and its whole reference graph** again as a separate MSBuild
configuration, writing into the same `obj/` folders as the normal build.

The two configurations wrote different `GeneratedMSBuildEditorConfig.editorconfig`
contents (`EnableArkToolsCompliance` differs for `Ark.Tools.Compliance.Analyzers`),
so the analyzer was recompiled on every build. It is injected repo-wide as an
analyzer, so every project recompiled after it: a no-op build re-ran 172 of 194
`Csc` invocations.

The binlog showed it as three instances of `Ark.Tools.Compliance.Analyzers`
(and of every project under the two entity projects), two of them carrying
`ArkComplianceSqlOutputPath` as a global property.

### Fix

- `ArkGenerateComplianceSqlStandalone` (in `Ark.Tools.Compliance.Sql`) now
  returns the generated scripts. It globs them in its own body, because items
  created by an earlier request on the same project are not kept.
- The database project calls it **without** `Properties` and reads
  `TargetOutputs`, so MSBuild reuses the normal build of each entity project.
  `WriteLinesToFile` uses `WriteOnlyWhenDifferent` so the SQL build stays up to date.
- `docs/compliance/sql-policies.md` shows the same pattern to consumers. The old
  pattern still works; it is only slower.

The generated `CompliancePolicies.sql` is identical to the old output.

### Results

| Scenario | Before | After |
|---|---:|---:|
| Cold build (`dotnet build`, restored) | 5m03s | 4m17s |
| No-op rebuild | 2m21s | 36s |
| `Csc` calls in a no-op rebuild | 172 | 3 (Azure Functions `WorkerExtensions`, generated by the SDK) |
| `Csc` calls in a cold build | 194 | 171 |

### Other build settings

- `SkipUnchangedFilesOnCopyAlways=true` in the repository `Directory.Build.props`
  files: `CopyToOutputDirectory=Always` items (appsettings, Reqnroll, testconfig)
  are copied only when they differ. The SDK package default is unchanged.
- CI caches the NuGet package folder through `actions/setup-dotnet`, keyed by
  the `packages.lock.json` files.

### Considered and not changed

- `dotnet pack --no-build` in CI saves about 25 seconds, but `GenerateSbom`
  failed intermittently without the build step. Not worth the flakiness.
- `ILLink.RoslynAnalyzer` is the largest analyzer by CPU time (about 30% of
  analyzer time in a cold build). It enforces the trimming/AOT annotations, so
  it stays enabled.

## Hot paths

BenchmarkDotNet, `benchmarks/Ark.Tools.Benchmarks/HotPathBenchmarks.cs`,
in-process job, 15 iterations. Baseline is the previous `master` with the same
benchmark file.

| Benchmark | Before | After |
|---|---:|---:|
| `ArkAdaptiveSampler` root span | 218 ns | 145 ns |
| `ArkAdaptiveSampler` root span, 4 threads | 2,019 ns | 290 ns |
| `ArkSqlQueryLabel.Extract` | 185 ns, 264 B | 147 ns, 136 B |
| `JsonPolymorphicConverter` read | 1,217 ns, 320 B | 1,145 ns, 208 B |
| `ArkETag.ApplyResponseETag`, no `If-None-Match` | 153 ns, 216 B | 54 ns, 72 B |
| `ToDataTablePolymorphic`, 1,000 rows of 2 derived types | 575 µs, 361 KB | 454 µs, 281 KB |

Changes:

- `ArkAdaptiveSampler`: look up the bucket before reading
  `ConcurrentDictionary.Count`, which takes every internal lock.
- `ArkSqlDependencyFilterProcessor`: split the configured server once in the
  constructor instead of per SQL span. `ArkSqlQueryLabel`: span-based
  `IndexOfAny` instead of a new `char[]` per line.
- `JsonPolymorphicConverter` and `ToObject<T>` on `JsonElement`/`JsonDocument`:
  deserialize from the element instead of copying it to a string first.
- `ShredObjectToDataTable`: extend the table and read members once per derived
  runtime type instead of per row.
- `ArkETag`: `SearchValues` token validation and an early return when
  `If-None-Match` is absent. `ArkMessagePackEx`: skip the `Accept` split when the
  media type is not present.
- `ETagHeaderBasicSupportFilterAttribute` (global MVC filter): static method
  lists, one pass over action arguments, typed headers only when used.
- `ResourceWatcherDiagnosticSource`: tag names are snake-cased once when the
  payload mapper is compiled; activity names are cached.
- `StorageQueueEnvelopeCodec`: one shared strict `UTF8Encoding`.
- `ArkGrpcErrorInterceptor`: violation properties discovered once per type.
- `DefaultAuthorizationService`: skip the claim lookups for Trace-level logs when
  Trace is off.
- Compliance analyzers: cheap checks before expensive ones in
  `SinkTaintAnalyzer`, `TestDataComplianceAnalyzer` and
  `DeclarationComplianceAnalyzer`.

## Follow-ups (not done here)

- MediatorFramework generators (`McpToolGenerator`, `MinimalApiEndpointGenerator`,
  `RebusEndpointGenerator`, `MessagingNetworkGenerator`) carry symbols or
  non-equatable models through their pipelines, or combine `CompilationProvider`
  into the output. They redo all work on every compilation, which costs IDE
  responsiveness. `GrpcEndpointGenerator` already shows the equatable-model pattern.
- `ComplianceSurfaceGenerator` does semantic work on every type even when
  `ArkComplianceSurfaceEnabled` is not set; gating it changes the generated file.
- `EvolvableEnum` conversions and its JSON, Dapper and MessagePack serializers box
  per value; `Unsafe.BitCast` and generic helpers would remove that.
- `Auth0AccessTokenJwtEvents` creates an `HttpClient` per user-info cache miss.
