# AZM-12 — Concurrency-safe Service Bus resource lifecycle

**Category**: azure-functions-messaging · **Priority**: core
**Depends on**: AZM-01, AZM-02, AZM-10
**Scope**: RUNTIME + HOSTING
**Design**: [Resource lifecycle](../../azure-functions-messaging-design.md#8-resource-lifecycle)

## Problem

Participants may start concurrently and must dynamically manage their event
subscriptions without deleting resources owned by another participant.

## Execution map

- **Runtime project**: implement management reconciliation in
  `Ark.Tools.MediatorFramework.Messaging`; consume only the generated
  manifest from AZM-10 through the AZM-05 transport management seam.
- **Ownership**: consumer participants (declaring `Processes` or
  `Subscribes`) own their identity queue and forwarding
  subscriptions. Topics of events declared in a member's `Publishes` may be
  `Ensure`d by the
  owning publisher **or** by any subscriber (create if missing only).
  Publisher-only participants own topics but no queue and no subscription.
  Sender-only participants
  own no entity. Queues and topics are never auto-deleted.
- **Reconciliation order**: validate configuration → ensure identity queue →
  ensure declared topics (publisher or subscriber) → ensure/update
  forwarding subscriptions → delete obsolete **subscriptions** proven to be
  participant-owned, including in production. No rolling dual-subscription
  grace:
  an obsolete subscription would keep delivering unhandled events into the
  identity queue and spike the DLQ.
- **Accepted rollout risk**: both removal and addition can be incompatible
  with old processors. Removing a subscription can race with an old host that
  still expects it; adding one can deliver an event that an old host cannot
  process. Deployment must stop/drain incompatible versions or use versioned
  identities/contracts.
- **Failure policy**: authorization, naming, incompatible existing entity
  settings, and partial reconciliation fail startup with structured
  diagnostics.
- **Stop condition**: never delete queues/topics automatically and never
  mutate Rebus-managed resources.

## Implementation steps

1. Define the generated desired-resource manifest for participant identity
   queues,
   owned topics, and subscriptions forwarding to identity queues.
2. Add startup registration that can ensure declared queues/topics/subscriptions
   exist while allowing IaC-managed deployments. Topic `Ensure` is allowed
   from publisher and subscriber participants; it must not delete or mutate a
   pre-existing foreign/IaC topic.
3. Derive deterministic subscription names from participant identity and
   topic, using
   only Azure-supported names.
4. Mark subscriptions with ownership metadata where Azure supports it and
   restrict deletion to subscriptions demonstrably owned by the current
   participant
   identity. Never delete queues or topics.
5. Remove obsolete participant-owned subscriptions after the desired set is
   known,
   including in production. Never remove an arbitrary or foreign
   subscription.
6. Make create/update/delete operations safe under concurrent startup from
   multiple instances and participants.
7. Expose diagnostics for management failures and avoid silently treating
   authorization or naming failures as success.
8. Apply the owning participant's retry policy to queue/subscription maximum
   delivery count
   and validate PeekLock-compatible entity settings.
9. Keep queues/topics optionally IaC-precreated; startup ensure must be
   idempotent.
10. Treat event logical-name changes as explicit topology migrations.
    `FormerNames` affects contract deserialization only; never auto-rename,
    merge, or delete an old topic.
11. Document that subscription reconciliation is not a deployment
    orchestrator and provide stop/drain or versioned-identity rollout guidance.

## Core code shapes

Conceptual shapes — final public names are selected by this task; the
signatures' invariants are fixed. Snippets use the AZM-05
`IMessagingTransportManagement` seam and consume the deterministic manifest
generated by AZM-10.

Service Bus implementation of the management seam over
`ServiceBusAdministrationClient` — idempotent create-if-missing, never
mutating or deleting a pre-existing foreign/IaC entity:

```csharp
namespace Ark.MediatorFramework.Messaging;

/// <summary>Azure Service Bus implementation of the transport management seam.</summary>
public sealed class ServiceBusTransportManagement : IMessagingTransportManagement
{
    private readonly ServiceBusAdministrationClient _admin;

    /// <summary>Creates the management seam over an application-composed admin client.</summary>
    public ServiceBusTransportManagement(ServiceBusAdministrationClient admin)
    {
        _admin = admin;
    }

    /// <inheritdoc/>
    public async Task EnsureQueueAsync(string queue, CancellationToken ctk)
    {
        var options = new CreateQueueOptions(queue)
        {
            // 2N when the owning participant enables second-level retries, else N.
            MaxDeliveryCount = _entityMaxDeliveryCountFor(queue),
        };
        try
        {
            await _admin.CreateQueueAsync(options, ctk).ConfigureAwait(false);
        }
        catch (ServiceBusException ex)
            when (ex.Reason == ServiceBusFailureReason.MessagingEntityAlreadyExists)
        {
            // Concurrent starter or IaC-precreated entity: ensure is idempotent and
            // never changes settings of an existing entity.
        }
    }

    /// <inheritdoc/>
    public async Task EnsureTopicAsync(string topic, CancellationToken ctk)
    {
        try
        {
            await _admin.CreateTopicAsync(new CreateTopicOptions(topic), ctk).ConfigureAwait(false);
        }
        catch (ServiceBusException ex)
            when (ex.Reason == ServiceBusFailureReason.MessagingEntityAlreadyExists)
        {
            // Publisher or any subscriber may Ensure: create-if-missing only.
        }
    }

    /// <inheritdoc/>
    public async Task EnsureSubscriptionAsync(
        string topic, string subscription, string forwardToQueue, CancellationToken ctk)
    {
        var options = new CreateSubscriptionOptions(topic, subscription)
        {
            // Every subscription forwards into the subscriber's identity queue.
            ForwardTo = forwardToQueue,
        };
        try
        {
            await _admin.CreateSubscriptionAsync(options, ctk).ConfigureAwait(false);
        }
        catch (ServiceBusException ex)
            when (ex.Reason == ServiceBusFailureReason.MessagingEntityAlreadyExists)
        {
        }
    }

    /// <inheritdoc/>
    public async Task DeleteSubscriptionAsync(string topic, string subscription, CancellationToken ctk)
    {
        try
        {
            await _admin.DeleteSubscriptionAsync(topic, subscription, ctk).ConfigureAwait(false);
        }
        catch (ServiceBusException ex)
            when (ex.Reason == ServiceBusFailureReason.MessagingEntityNotFound)
        {
            // Already removed by a concurrent instance of the same participant.
        }
    }
}
```

Startup reconciliation flow, consuming the generated desired-resource
manifest in the fixed order:

```csharp
/// <summary>Reconciles the generated desired-resource manifest at startup.</summary>
public sealed class MessagingResourceReconciler
{
    private readonly IMessagingTransportManagement _management;

    /// <summary>Runs validate -> queue -> topics -> subscriptions -> obsolete cleanup.</summary>
    public async Task ReconcileAsync(MessagingResourceManifest manifest, CancellationToken ctk)
    {
        // 1. Identity queue (consumer participants only; sender-only owns no entity).
        if (manifest.IdentityQueue is { } queue)
        {
            await _management.EnsureQueueAsync(queue, ctk).ConfigureAwait(false);
        }

        // 2. Declared topics: owning publisher OR any subscriber, create-if-missing.
        //    A subscriber starting before the publisher can therefore proceed.
        foreach (var topic in manifest.Topics)
        {
            await _management.EnsureTopicAsync(topic, ctk).ConfigureAwait(false);
        }

        // 3. Forwarding subscriptions into this participant's identity queue.
        foreach (var subscription in manifest.Subscriptions)
        {
            await _management.EnsureSubscriptionAsync(
                    subscription.Topic, subscription.Name, manifest.IdentityQueue!, ctk)
                .ConfigureAwait(false);
        }

        // 4. Delete obsolete subscriptions owned by this participant, in production too.
        await _deleteObsoleteOwnedSubscriptionsAsync(manifest, ctk).ConfigureAwait(false);
    }
}
```

Deterministic subscription-name derivation (conceptual; deterministic but not
public contract API):

```csharp
// topic:        <publisher-identity>-<contract-name>
//               e.g. "web-frontend-book_print_completed"
// subscription: <subscriber-identity>
//               e.g. "printing"
public static string DeriveSubscriptionName(string subscriberIdentity)
{
    // The subscriber identity is unique inside the network and already satisfies the
    // portable queue-name contract (3-50 lowercase letters/digits/hyphens), so it fits
    // the Service Bus 50-character subscription-name limit and identifies ownership.
    return subscriberIdentity;
}
```

Obsolete-subscription deletion restricted to subscriptions demonstrably owned
by the current participant identity:

```csharp
private async Task _deleteObsoleteOwnedSubscriptionsAsync(
    MessagingResourceManifest manifest, CancellationToken ctk)
{
    // Enumeration is a Service Bus management operation surfaced beside the seam;
    // only topics known to the network declaration are inspected.
    foreach (var topic in manifest.KnownNetworkTopics)
    {
        await foreach (var subscription in _admin.GetSubscriptionsAsync(topic, ctk)
            .ConfigureAwait(false))
        {
            var isOwned = string.Equals(
                subscription.SubscriptionName, manifest.ParticipantIdentity,
                StringComparison.Ordinal);
            var isDesired = manifest.Subscriptions.Any(d =>
                d.Topic == topic && d.Name == subscription.SubscriptionName);

            // Delete only owned + no-longer-desired; foreign subscriptions, queues,
            // and topics are never deleted. Not-found races with concurrent instances
            // of the same participant are swallowed by DeleteSubscriptionAsync.
            if (isOwned && !isDesired)
            {
                await _management.DeleteSubscriptionAsync(
                        topic, subscription.SubscriptionName, ctk)
                    .ConfigureAwait(false);
            }
        }
    }
}
```

Concurrency-safety pattern: every create catches
`MessagingEntityAlreadyExists`, every delete catches
`MessagingEntityNotFound`, and any other `ServiceBusException` (authorization,
naming, quota, incompatible entity settings) propagates and fails startup with
a structured diagnostic — races are benign, real failures are never silently
treated as success.

## Required test coverage

- Concurrent ensure from multiple instances of one participant.
- Two participants subscribing to one topic without deletion races.
- Every subscription forwards to its participant identity queue.
- Multiple topics for one participant.
- Obsolete owned subscription removal.
- Foreign subscription preservation.
- Missing permissions, invalid names, and transient management failures.
- Restart after partial resource creation.
- Event logical-name migration leaves old topics untouched and requires an
  explicit operator plan.
- A subscriber participant starting before the publisher can `Ensure` the
  topic
  and then create its forwarding subscription.
- Obsolete owned subscriptions are deleted on reconcile in production.
- Addition/removal rollout guidance covers old-processor incompatibility in
  both directions.

## Caveats

- Confirm Azure Service Bus management API limitations and eventual consistency
  before finalizing the naming/ownership implementation.
- Production deletion is allowed only for participant-owned resources.

## Outcomes

- Event subscriptions follow participant configuration dynamically.
- IaC and runtime startup provisioning can coexist safely.
- Scale-out does not create duplicate unmanaged subscriptions or destructive
  cross-participant races.
